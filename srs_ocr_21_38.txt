Appendix D: System Architecture

The Complaint Management System follows a classic two-tier client-server
architecture

© Client Tier (Frontend): This layer is a browser-based application built with
React,js. It is responsible for all user-facing interactions, rendering the Ul
and managing the application's state. It communicates with the backend via
RESTful API calls. The frontend is responsive and optimized for a variety of
devices.

© Server Tier (Backend): This layer is a robust, stateless application built with
Spring Boot. It is responsible for all business logic, data validation, security,
and communication with the database. It exposes a set of REST endpoints
that are consumed by the frontend. This tier is designed to be highly scalable
and is deployed in a containerized environment (e.g., Docker),

* Data Tier (Database): This layer consists of a MySQL database instance. It
is responsible for the persistent storage of all system data. The backend
server is the only component with direct access to the database. The schema
is designed to be normalized and efficient for the system's core functions.
